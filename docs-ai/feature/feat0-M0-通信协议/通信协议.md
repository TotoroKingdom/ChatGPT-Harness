# 已冻结的 M0 决策

这些不需要重新讨论，直接实现。

## 1. 参考 Codex app-server

UI ↔ Runtime Control Protocol 直接参考 OpenAI Codex `app-server` 的设计模式。

架构：

```text
React UI
   ↓
HarnessControlClient
   ↓
Tauri Backend
   ├─ Config Authority
   ├─ SecretStore Authority
   └─ Runtime Process Supervisor
          ↓ spawn
     Harness Runtime
          ↕
     stdin / stdout
     UTF-8 JSONL
     JSON-RPC 2.0 semantics
```

同时：

```text
ChatGPT
   ↓
tunnel-client
   ↓
MCP
   ↓
Harness Runtime
```

`Control Protocol` 与 `MCP Protocol` 是两个独立协议面，不要混合。

---

## 2. Runtime 生命周期

Tauri Backend 拥有 Runtime process lifecycle。

因此：

- `runtime.start` 是 `HarnessControlClient` facade method。
- `runtime.start` 不属于 Runtime wire RPC，因为 Runtime 尚未启动时无法接收 RPC。
- Tauri Backend 负责 spawn Runtime。
- Runtime 启动后通过 stdio Control Protocol 通信。
- `runtime.stop` 是 Runtime wire RPC，用于 graceful shutdown。
- Runtime 无响应时的 kill/process cleanup 属于后续实现，不属于 M0。

---

## 3. Transport

V1 Control Protocol：

```text
stdin / stdout
```

Framing：

```text
UTF-8 JSONL
```

规则：

- 一行一个完整 JSON message。
- stdin = client → Runtime。
- stdout = Runtime → client。
- stdout 只能输出 protocol message。
- Runtime 日志必须走 stderr。
- M0 不实现 Named Pipe / localhost HTTP / WebSocket / gRPC。

---

## 4. RPC Envelope

参考 Codex：

使用 JSON-RPC 2.0 semantics，但 wire 上省略：

```json
"jsonrpc": "2.0"
```

支持：

- Request
- Response
- Notification
- Error Response

Request ID 支持：

- integer
- string

至少定义：

```rust
RequestId
RpcRequest
RpcResponse
RpcNotification
RpcErrorResponse
RpcError
RpcMessage
```

标准 RPC error code 至少支持：

```text
-32700 Parse error
-32600 Invalid request
-32601 Method not found
-32602 Invalid params
-32603 Internal error
```

Harness-specific RPC error 使用 `-32000..-32099`。

`error.data` 中提供稳定 machine-readable code。

至少：

```text
NOT_INITIALIZED
ALREADY_INITIALIZED
PROTOCOL_VERSION_MISMATCH
RUNTIME_NOT_READY
INVALID_ARGUMENT
APPROVAL_NOT_FOUND
APPROVAL_ALREADY_RESOLVED
INTERNAL_ERROR
```

# 5. initialize handshake

连接建立后必须：

```text
spawn Runtime
→ initialize request
← initialize response
→ initialized notification
→ ready
```

在 initialize 完成前，除 `initialize` 外的业务 request 必须被拒绝。

协议版本：

```text
protocolVersion = 1
```

V1 使用严格相等：

```text
client == server → compatible
client != server → initialization failure
```

不要实现 downgrade / migration / multi-version compatibility。

App version 和 protocol version 分开。

### InitializeParams

至少：

```text
clientInfo
protocolVersion
capabilities
runtimeConfig
```

ClientInfo：

```text
name
title
version
```

### InitializeResult

至少：

```text
serverInfo
protocolVersion
runtimeId
capabilities
```

Capabilities 只用于非安全关键 optional behavior。

安全核心能力，例如 Workspace Guard / Policy / fail-closed，不允许设计成可协商关闭。

---

# 6. Config ownership

唯一 Persistent Config Authority：

```text
Tauri Backend
```

必须保持：

```text
AppConfig
!=
RuntimeConfigSnapshot
!=
RuntimeState
```

Frontend 不直接读取或修改配置文件。

Runtime：

- 不持久化 AppConfig。
- 不修改 AppConfig。
- 只消费启动时收到的 `RuntimeConfigSnapshot`。

RuntimeConfigSnapshot 通过 `initialize` request 下发。

API Key 不允许进入 RuntimeConfigSnapshot。

---

# 7. AppConfig

定义 versioned AppConfig model，至少：

```text
AppConfig
├─ schemaVersion
├─ configRevision
├─ workspace
├─ tunnel
├─ security
└─ ui
```

最低字段：

```text

- rootPath

TunnelConfig
- tunnelId
- tunnelClientPath
- autoDetect
- apiKeyRef

SecurityConfig
- mode
- developerTestMode
```

`apiKeyRef` 是 SecretStore reference。

禁止保存：

```text

```

M0 只冻结：

- machine-local
- OS application-data location
- outside Git repository

不要实现具体 SecretStore backend。

# 8. RuntimeConfigSnapshot

至少：

```text
configRevision
workspace
security
runtimeLimits
```

不得包含：

- API Key
- raw secrets
- UI preference
- 不属于 Runtime 的 tunnel credential

RuntimeState 必须能够报告当前使用的 `configRevision`。

因此以后：

```text
AppConfig revision != RuntimeState revision
```

可以表达为：

```text

restartRequired = true
```

# 11. activity.list / subscribe

`activity.list` Params：

```text
afterSequence?
limit?
```

Result：

```text
items
latestSequence
```

`activity.subscribe` Params：

```text
afterSequence?
```

订阅后：

1. 补发 `afterSequence` 后尚未消费的 event；
2. 再通过 `activity.event` notification 持续发送实时 event。

连接关闭自动取消订阅。

M0 不需要设计 unsubscribe。

# 12. approvals

`approvals.list`

支持：


`approvals.resolve`

Params：


```text

```

# 14. Serialization conventions

统一：

```text
Rust fields      snake_case
JSON fields      camelCase
enum values      snake_case

IDs              opaque strings
Option::None     omitted
```

# 15. Generated TypeScript + JSON Schema

参考 Codex。

Rust protocol model 是唯一 source of truth。

需要可以显式执行：

```text
cargo run -p harness-control-protocol --bin protocol-export -- generate-ts
cargo run -p harness-control-protocol --bin protocol-export -- generate-json-schema
cargo run -p harness-control-protocol --bin protocol-export -- generate-all
```

输出到：

```text
protocol/generated/typescript/
protocol/generated/json-schema/
```

generated file 标记：

```text

```

禁止在 `build.rs` 中自动修改 working tree。
